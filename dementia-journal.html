REWIND: Memory Exercises Built From Your Own Life

Generic cognitive exercises are easy to disengage from. REWIND generates recall questions from the patient's own diary entries instead.

Role
Sole developer & designer
Timeline
Fall 2024 – Spring 2025
Stack
Python · Flask · Firebase · Gemini API · HTML/CSS
Status
Functional prototype

The Problem

Dementia affects more than 55 million people worldwide, and the figure is projected to triple by 2050. Memory loss is progressive, but regular retrieval practice is associated with slower decline and better quality of life — if patients keep doing it.

That last condition is where existing tools fall down:

  • Generic exercises. Recalling a word list has no connection to a patient's life, so there's nothing pulling them back to it.
  • No personalization. Without personal relevance, engagement drops off quickly — and an exercise nobody does has no effect.
  • Fixed difficulty. A single difficulty level is wrong for almost everyone, and stays wrong as the condition progresses.
  • Caregivers flying blind. No visibility into what a patient can still recall means no data to inform care decisions.

The Approach

REWIND pairs a daily journal with AI-generated recall quizzes drawn from what the patient actually wrote. The diary supplies the source material, so every question is about something the person genuinely experienced — which makes the exercise both more meaningful and a more honest measure of recall.

Key features

Accessible diary entry

A deliberately plain interface for recording daily experiences — large text, high contrast, minimal navigation.

Generated recall questions

Gemini generates quiz questions from the patient's own entries rather than a fixed question bank.

Four difficulty tiers

Each tier draws from a different window of history, from one week back out to three months.

Progress tracking

Quiz performance recorded over time, so retention trends are visible rather than anecdotal.

Authenticated cloud storage

Firebase Auth and Firestore keep entries private to the user and available across devices.

Caregiver dashboard

Planned, not built — designed for clinicians to review cognitive trends over time.

The core idea

Difficulty here isn't an abstract setting — it's a time window. A harder quiz asks about something further back. That maps difficulty directly onto the thing dementia actually affects, and it means the difficulty tiers double as a rough measure of how far back reliable recall extends.

Building It

Designing for cognitive load

Every interface decision assumed a user who may be confused or disoriented. Large text, high contrast, one action per screen, and no nested navigation. Features that would have been useful for a caregiver were deliberately kept off the patient's screens — an interface that tries to serve both audiences at once serves neither.

Architecture

  1. Flask backend — lightweight server-side logic, quick to iterate on
  2. Firebase Authentication — user management without hand-rolling credential storage
  3. Firestore — diary entries and quiz results, queryable by date range
  4. Gemini API — question generation from retrieved entries
  5. Responsive frontend — works on whatever device the patient already has

The generation step

The interesting engineering is in the middle. The system pulls entries within the selected time window, passes them to Gemini with a prompt shaped to produce specific, factual recall questions rather than open-ended reflection, and returns the result as a quiz. Getting questions that test detail — rather than asking how the day felt — took real iteration on the prompt.

What Works, and What Doesn't Yet

Built

  • Authenticated multi-user accounts
  • Diary capture and retrieval by date range
  • Question generation across four difficulty tiers
  • Quiz scoring and history

Not yet built

  • Caregiver-facing dashboard
  • Trend visualization over time
  • Native mobile application

Not yet validated

  • No testing with dementia patients or caregivers
  • No clinical evidence of cognitive benefit
  • Accessibility assumptions untested with the target population
Honest assessment

This is a working technical prototype resting on an untested premise. The engineering — auth, storage, generation, scoring — is real and functional. Whether personalized recall practice actually helps patients is a clinical question this project does not answer, and testing with real users is the necessary next step before any claim about benefit would be justified.

What I'd Do Next

  • Test the interface with dementia patients and caregivers — the accessibility choices are informed guesses until someone in the target population uses it
  • Build the caregiver dashboard, the feature most likely to make the tool clinically useful
  • Add trend visualization so recall changes are visible at a glance
  • Investigate EHR integration for clinical settings

Technically, the most valuable thing I took from this was prompt engineering as a real design surface. The difference between a question that tests recall and one that invites a vague reflection is entirely in how the request is framed — and that framing needed as much iteration as any part of the interface.
